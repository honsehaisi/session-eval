## 模板 v2 为什么改（2026-11-12 实测）

v1 写「不要读工作区文件」。实测：**子代理没有记忆注入**（直接问「你有没有注入」，它答「没有」；问 B 站 mid 答「不知道」）。不读文件就等于没有记忆，55 题会大面积答「不知道」——两次都答「不知道」会被判 `same`，一致率虚高。

v2 改成：**允许查 `<你的记忆库路径>`，禁止读 `.dsh` 与工作区其它文件**。这才是「一个新会话的真实作答」（真实新会话 = 有记忆 + 会去查）。

> 残余风险：题目在 `系统测评/src/memory/questions.json`，位于 `.dsh` 下，已整棵禁止；但这是**指令级**隔离，不是物理隔离（§7.6 那条坑还没根治）。抽检时留意回答里有没有出现题库特有的 source 行号。

## 跑 T0′（已完成，2026-11-12 18:30–19:05）

```bash
node 系统测评/src/consistency/snapshot.js --tag t0b
node 系统测评/src/consistency/ask.js      --tag t0b
# 作答：子代理代答，7 个批次（8/8/8/8/8/8/7 题），cwd 在 %TEMP% 空目录
# → 汇总成 answers-t0b.json
```

**为什么分批而不是 55 个独立会话**：子代理并发上限 8；且每题都要查库，分批后条件一致、成本低一个量级。T1 **必须用同样分批**，否则比较的是结构差。

**`verdict` 字段**：T0′ 统一记 `hit`（表示「有作答」）。一致性只由 `answer` 的数字集与措辞决定（`lib.classify`），**不在汇总时人工分桶**——分桶带主观性，会让两次判定不可复现。

## 判分口径（§6.2 判定条，v3 = 2026-11-19）

1. 先人工判**全量**当金标准（本轮 55 题），规则与人工一致才准自动判全量。
2. 规则判三个桶：`same`（关键数字对得上）、`review`（发现矛盾但措辞近，需人核）、`diff`（数字互不相干 / 判定类型不同）。
3. `score.js` 出两个数：`strict`（只算 same，最保守）和 `loose`（same + review）。**正式数字用哪个由人工对齐后定**。

### v3 与 v2 的三处差别（v2 实测 strict 47.3% / E，全是假红）

| 改法 | 为什么 |
|---|---|
| **先剥出处括注**：`（identity/accounts.md：…）` 这种整段不算答案 | T0′ 爱把出处挂在结论后面，里面的页号/路径/版本号全是数字，旧规则一比就「数字不同」 |
| **关键数字去噪**：日期 `2026-11-05`、时刻 `23:00`、版本号 `v1.8`、章节号 `§8.6` 不算；小数允许取整差（`9.5 分钟` ↔ `9 分半`，仅限一边是整数、差 ≤ 0.5） | 这些不是结论；但 **2.77 ↔ 2.87 是真差**，不许放过 |
| **实体先判**：两边都点到程序/文件名（`.exe/.bat/.mjs/.md`）且一个都不重合 → `review` | F-005 那种「`NapCatWinBootMain.exe` ↔ `napcat.bat`」是真分歧，不能因为数字对得上就白给 same |

判 `same` 的判据只有一条：关键数字**一方能覆盖另一方**（另一方只是补充细节）。互不相干时再看措辞距离：`sim < 0.15` → `diff`，否则 `review` 交人工。

### 已知边界（必须说清，否则就是假绿）

- 纯文字对（双方都没有关键数字）v3 没有可比的硬证据，只能报「无冲突」——本批 **20/55（36%）** 是这一类。v3 排除矛盾，**不证明等价**；正式数仍以人工全量判的 `judge-t1-manual.json` 为准。
- v3 是在本批 55 题上对着人工结论调的，**同一批数据不能当独立验证**。下次换库/换题先抽 20 题人工判，规则与人工一致率 ≥ 95% 再跑全量（§6.2 原文）。
- 出处剥除靠后缀白名单（`.md/.json/.exe…`）识别；哪天出处写成「`（见某页）`」不带后缀，就剥不掉——判分单测里留了普通括注不剥的反例。
- **2026-11-20 独立验证（同题库换作答，20 题）**：与人工全量判 **0 假绿、0 假红**
  （18 same + 2 保守 review；两条都是新答案多写了精确数字 `629,146` / `log.md:1368`，人工看结论一致）。
- **`verdict` 必须统一记 `hit`**（表示「有作答」），一致性只由 `answer` 决定。别拿 `autoVerdict`
  去填——那是记忆维「答对没」的口径，会把换说法的正确作答短路成 diff（2026-11-20 验证时踩过，8/20 假红）。
